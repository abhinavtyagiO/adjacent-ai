# Repository instructions

## Documentation standard

Write all new and updated documentation in plain English. Apply this standard across the repository, including the README, guides, API examples, and verification notes. Use [the Phase 2A guide](docs/phase2a.md) as a reference.

- Start with what the reader can do, then explain how to do it. Put implementation and troubleshooting details where readers will look for them.
- Use everyday words, active voice, short paragraphs, and descriptive headings. Explain acronyms and necessary technical terms when they first appear.
- Use numbered steps for workflows, tables for settings or endpoints, and realistic examples for inputs and outputs. Leave out filler and repeated explanations.
- Keep commands, paths, field names, status codes, limits, and warnings exact. Explain what they mean in plain English. State which settings are defaults and which inputs are required.
- Describe failures in terms of what the reader will see, what work is saved, and what action they can take. Distinguish what tests verified from what still needs a live check.
- Check links, examples, and technical details against the code before finishing a documentation change.
